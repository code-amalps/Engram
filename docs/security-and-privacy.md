# Security, Privacy & Data Handling in Engram

This document details Engram's local data storage, network footprint, secret redaction capabilities, ignore policies, and known limitations.

---

## 1. Network Activity & Data Boundary

- **Zero Outbound Telemetry or Cloud Transmission:** Engram contains no networking dependencies (no `reqwest`, `hyper`, or HTTP client crates in `Cargo.toml`). The runtime does not send source code, symbols, prompts, context payloads, or analytics to any external cloud service or server.
- **Local Subprocesses:** Engram executes the local `git` binary via `std::process::Command` to query commit hashes, diffs, and repository status (`git rev-parse`, `git status`, `git diff`, `git log`). It never invokes `git push`, `git fetch`, or network-bound Git commands.
- **MCP Communication:** Engram communicates with AI coding assistants (like Cursor, Claude Desktop, and Windsurf) strictly over standard input/output (`stdio`) using local JSON-RPC 2.0 messages.

---

## 2. What Data Is Stored Locally?

All data generated by Engram is stored directly within the target repository's `.engram/` directory:

1. **`.engram/index.db` (SQLite WAL):**
   - Relative file paths and content hashes (SHA-256).
   - Extracted symbol names, kinds (class, interface, method, function), start/end line numbers, and signature strings.
   - Relationship edges (imports, calls, implements, tests) with confidence scores and evidence tiers.
   - Redacted source code excerpts (truncated to the first 20,000 characters).
2. **`.engram/memory.yaml`:**
   - Permanent architectural decisions, rationale statements, scopes, author attribution, and supersession links.
3. **`.engram/constitution.yaml`:**
   - User-defined architectural rules and boundary constraints.
4. **`.engram/events/`:**
   - Append-only cryptographic audit logs (`evt_*.json`).
5. **`.engram/cache/`:**
   - Ephemeral caches, including active recovery sessions (`.engram/cache/recovery/*.json`).

## 3. Secret Redaction & Known Gaps

Before any source text excerpt enters SQLite storage or context payloads, Engram applies deterministic regex redaction (`src/analyzer.rs:redact`):

### Redacted Patterns:
- API Keys: OpenAI-style (`sk-...`), GitHub tokens (`ghp_...`, `gho_...`), and AWS Access Keys (`AKIA...`).
- Key-Value Credentials: JSON/YAML/INI assignments matching `password`, `secret`, `api_key`, `token` followed by quoted values.
- Database Connection URIs: `postgres://`, `mysql://`, `mongodb://`.
- Email addresses.

### Known Limitations & Security Warnings:
> ⚠️ **Heuristic Redaction Is Not a Silver Bullet:**  
> Regex pattern matching cannot detect all possible confidential information. Non-standard proprietary tokens, high-entropy random strings without standard prefixes, base64-encoded secrets, and private business data will **not** be caught by regex heuristics.  
> **Recommendation:** Always keep secrets in `.env` files or dedicated secret managers, and ensure sensitive files are excluded in `.engramignore`.

---

## 4. Default Ignore Rules

Engram enforces default ignore rules to prevent indexing sensitive or generated files:

- **Strict Exclusions:** `.env`, `.env.*`, `*.pem`, `*.key`, `.git/`, and binary files (containing null bytes or exceeding 2 MB) are never indexed.
- **`.engramignore`:** Follows standard `.gitignore` syntax to exclude dependency directories (`node_modules/`, `vendor/`), build artifacts (`target/`, `dist/`, `build/`, `bin/`, `obj/`), and logs.
- **Gitignore Respect:** If `.git` is present, Engram respects repository `.gitignore` rules in addition to `.engramignore`.
