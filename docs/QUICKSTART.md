# Engram 5-Minute Quickstart

Get Engram initialized, indexed, and providing intelligence to your AI workflow in under five minutes.

---

## Step 1: Initialize Your Workspace (`engram init`)

Navigate to the root directory of your project and initialize Engram:

```bash
cd /path/to/your/project
engram init
```

### What happens:
- Creates the local configuration and database directory: `.engram/`
- Generates a default `.engramignore` file containing sensible exclusions (`node_modules`, `target`, `.git`, `.env`, keys, certificates, binaries).
- Initializes the empty SQLite WAL database schema (`.engram/index.db`).
- Creates the architectural decision register template (`.engram/memory.yaml`).

### Expected Output:
```text
Initialized empty Engram workspace in /path/to/your/project/.engram
Created .engramignore with standard defaults.
Database initialized at .engram/index.db (WAL mode enabled).
```

---

## Step 2: Index Your Codebase (`engram analyze`)

Run baseline analysis to parse AST symbols and construct the dependency graph:

```bash
engram analyze
```

### What happens:
- Discovers all source files matching supported languages (Rust, TypeScript, JavaScript, Python, Go, Java, C#, C/C++).
- Parses Abstract Syntax Trees via Tree-sitter.
- Extracts symbols (functions, structs, classes, interfaces, traits, methods).
- Maps directional relationships (`Imports`, `Calls`, `Extends`, `Implements`, `Instantiates`, `UsesType`, `Overrides`).
- Persists index and graph into `.engram/index.db`.

### Expected Output:
```text
Analyzing repository...
Indexed 142 source files in 0.84s.
Extracted 1,842 symbols and 3,115 dependency relationships.
Index stored in .engram/index.db.
```

## Step 3: Query Grounded Context (`engram context`)

Retrieve budget-allocated AST context for an engineering task or question:

```bash
engram context "How does the SQLite storage engine handle WAL migrations?"
```

You can optionally specify a token budget:
```bash
engram context --budget 2000 "Change Contract validation state machine"
```

### Expected Output:
```markdown
<engram_context>
# Engram Grounded Context: Change Contract validation state machine
Generated by Engram v1.5.5-rc2 | Budget: 2000 tokens

## Primary Symbols
- `src/contract.rs:45-120` | `pub struct ChangeContract`

- `src/contract.rs:14-22`  | `pub enum ContractState`

## Dependency Relationships

- `contract::ChangeContract` -> `UsesType` -> `contract::ContractState`

## Architectural Decisions (ADRs)
- `ADR-004` (Accepted): Git diff baseline locks prevent branch switching races.

```

## Step 4: Inspect Symbol Impact & Graph Health (`engram inspect <TARGET>`)

Deeply inspect a symbol or file's downstream change impact, blast radius, causal provenance, and active contract status:

```bash
engram inspect add
# or inspect a specific file:
engram inspect src/storage.rs
```

## Step 5: Verify Health (`engram doctor`)

Run environment diagnostics to verify Git integration, SQLite integrity, and parser readiness:

```bash
engram doctor
```

## Exit Codes & CLI Troubleshooting

| Exit Code | Meaning | Common Resolution |
|:---:|---|---|
| `0` | Success | Command completed successfully. |
| `1` | General Error | Check command arguments, file paths, or run `engram doctor`. |
| `2` | Workspace Not Initialized | Run `engram init` in the root of your project first. |
| `3` | Contract Violation | Agent edited files outside declared change contract. Run `engram_check_change_contract`. |
| `4` | Git Error | Workspace is not a Git repository or Git is missing from PATH. |\n
